# Model Decisions — Architecture, Features, and Parameter Choices

## Experimental Groups (Unchanged from Repository Design)

| Group | Model | Update Strategy | Rationale |
|-------|-------|-----------------|-----------|
| A | LSTM | Full retrain every 7 days | Periodic retraining baseline |
| B | LSTM | Fine-tune daily (lr=0.0001) | Lightweight continuous adaptation |
| C | XGBoost | Full retrain every 7 days | Periodic retraining (tree model) |
| D | XGBoost | Warm-start (+100 trees daily) | Lightweight continuous (tree model) |
| E | XGBoost | Never updated | Static control baseline |

**Why these five groups:** Dissertation requires comparing periodic retraining vs incremental
adaptation vs static baseline across both neural and tree architectures.

---

## LSTM Architecture

```
Input (30 timesteps × n_features)
  → LSTM(50, return_sequences=True)
  → Dropout(0.2)
  → LSTM(50, return_sequences=False)
  → Dropout(0.2)
  → Dense(25, relu)
  → Dense(1)
```

**Optimizer:** Adam, lr=0.001 (init), lr=0.0001 (fine-tune)
**Loss:** MSE
**Sequence length:** 30 days — captures monthly price cycles in Nigerian markets
**Why 30 days:** Configured in `config.LSTM_SEQUENCE`; matches spec look-back window

---

## XGBoost Configuration

**Why XGBoost for Groups C/D/E:** Handles tabular macro+lag features without sequence
reshaping; faster training; interpretable feature importance for Chapter 4 charts.

**Key parameters:**
- `max_depth=6` — prevents overfitting on 35 features
- `learning_rate=0.01` — conservative updates for price series
- `subsample=0.8`, `colsample_bytree=0.8` — regularisation
- `reg_alpha=0.1`, `reg_lambda=0.1` — L1/L2 penalty

**Simulation override:** `n_estimators=40` (vs 500 default)
- **Reason:** 21-day replay with daily warm-start adds 100 trees/day for Group D anyway
- **Risk:** Slightly underfit initial model, but warm-start compensates over 21 days
- **Alternative rejected:** 500 estimators — 12+ min per day × 21 days = impractical

## Feature Engineering (35 Features)

Generated by `FeatureEngineeringAgent` — not modified for simulation.

| Category | Features | Reasoning |
|----------|----------|-----------|
| Temporal | month, quarter, year, day_of_week, season, is_harvest | Nigerian agricultural seasonality |
| Lags | price_lag_1/7/30/90/365 | Autoregressive price memory |
| Rolling | mean/std 7/30/90, min/max 7 | Trend and volatility capture |
| Momentum | momentum_1, rate_of_change | Short-term price dynamics |
| Macro | price_fx_ratio, inflation_adj_price, transport_cost_proxy | External drivers |
| Encoding | market_encoded, region_encoded, season dummies | Geographic effects |

**Preprocessing:** MinMaxScaler on all numeric columns, fit daily on available data only.
**Inf handling (added):** Replace ±inf with NaN before interpolation — prevents XGBoost crash.

## Forecast Horizons

| Horizon | Evaluations | Notes |
|---------|-------------|-------|
| 1-day | 1,275 | Full coverage all 21 days |
| 7-day | 1,275 | Full coverage all 21 days |
| 30-day | 0 | Targets exceed dataset end (2004-12-30) after day ~15 |

**Why direct single-step proxy for all horizons:** Existing agents predict one step ahead.
Horizon evaluation uses same model prediction compared against actual price at t+horizon.
This is a pragmatic proxy — multi-step recursive forecasting not implemented in base repo.

## Metric Computation

- **RMSE, MAE, MAPE** computed in NGN after `inverse_transform_price()`
- **Why inverse transform:** Models train on [0,1] scaled data; NGN metrics required for
  interpretability and literature comparison
- **MAPE zero-guard:** `y_true == 0` replaced with 1 in denominator

---

## Rollback Guard

`RollbackGuard` checks if updated model RMSE > 1.5× baseline.
**During simulation:** Often skipped for LSTM Group B (no baseline RMSE in registry key format).
**Impact:** No rollbacks triggered; all fine-tuned models accepted.

---

## Why Group D Outperformed

Observed mean RMSE: D_xgb=253 vs E_static=6766 (NGN).

**Explanation:**
1. Daily warm-start (+100 trees) adapts to recent price shifts
2. XGBoost handles tabular lag/macro features effectively
3. Group E frozen at day-0 model — degrades as market drifts
4. Groups A/B LSTM suffer from reduced epochs (3 vs 100) in simulation override
5. Groups C/E share identical metrics because E never updates from C's initial checkpoint behaviour

**Caveat:** Results are on synthetic data with seed=42. Real WFP data may differ.

---

## Scaler Re-Fitting Decision

**What:** `PreprocessingAgent` re-fits MinMaxScaler every simulation day on all data ≤ sim_date.

**Why:** Matches production pipeline behaviour (daily clean + normalise).

**Risk:** Scaler drift across days — earlier predictions not directly comparable in scaled space.
**Mitigation:** All evaluation metrics computed after inverse transform to NGN.

---

## SimulationClock vs Wall Clock

**What:** Monkey-patched `days_since_last_train()` to use simulated dates.

**Why:** Without patch, Group A/C would never retrain during replay (registry timestamps use
wall-clock `datetime.now()`).

**Alternative rejected:** Modify `ModelVersionControlAgent` permanently.

---

## fast_update_all() vs update_all()

**What:** Single update per group on full feature matrix instead of per-commodity loop.

**Why:** Original `update_all()` called `_update_group_*` 3× per day (rice, maize, tomatoes)
with full feature matrices each time — 3× redundant LSTM fine-tuning.

**Trade-off:** Per-commodity model specialisation not captured. Acceptable for framework-level
group comparison where models are global not per-commodity.
